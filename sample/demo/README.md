# Original synthetic onboarding demo

This small, redistributable fixture supplies real simulator games without an
Arena-derived pack. It contains eight original vanilla creatures, one original
mana-producing land, and two 40-card decks (17 lands and 23 creatures each).
It is **not a Magic set, fidelity measurement, or bot-strength benchmark**.
Use it to learn the protocol and check that your bot starts and answers legally.

All names, numeric identities, costs, stats, and deck lists were authored for
this demo. No Arena/Scryfall data, mined decks, card art or printed card text
was read or incorporated. IDs `0xFD100000` through `0xFD100008` are local demo
identities, not Arena IDs; do not merge them into real card datasets. The land
uses a tap cost and the engine's closed `ManaAbility` operation for one unit
of colorless mana. Creatures use generic costs and no special abilities.
The artifact and this documentation are provided under the repository's MIT license.

From the botkit checkout root, with the downloaded host on PATH:

```bash
botkit decks --pack sample/demo/sim_DEMO.json --out demo-decks.json
botkit validate --pack sample/demo/sim_DEMO.json --decks demo-decks.json --bot "ext:python random_bot.py" --cwd examples/python
botkit match --pack sample/demo/sim_DEMO.json --decks demo-decks.json --a beginner --b quick --pairs 2 --seed 7
```

In the DeckLogic source checkout these paths are `bots/sample/demo/` and
`bots/examples/python/`. PowerShell can run an explicit host path with
`& '.\path\to\botkit.exe'` followed by the same arguments.

The checked-in JSON is usable directly; bot authors do not need Rust or the
engine source. Maintainers regenerate both JSON files from the original
recipe in `src-tauri/botkit/examples/make_demo_pack.rs`:

```bash
cargo run -p decklogic-botkit --example make_demo_pack -- bots/sample/demo
cargo test -p decklogic-botkit --test demo_pack
```

The generator reads no external data and seals the pack with its canonical
body checksum. It produces deterministic JSON, including a curated-deck
provenance label and unset fidelity measurement. The regression test compares
the regenerated bytes with both committed artifacts. Compatibility with the
public Windows v213 host is checked separately in the audit report; future
wire-format changes require repeating that check before updating this demo.

Verified with the public Windows `sim-engine-v213` host (ABI 212): deck/card
export and default Python-example validation pass, and a two-pair built-in
match completes without faults or caps. One of validation's 20 random-play
games reached the engine cap; the bot still passed all acceptance checks.
This is execution evidence only, not a strength comparison.
